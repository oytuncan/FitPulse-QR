## Project

FitPulse QR is a Flutter app (Dart SDK ^3.13.7) backed by Firebase. Right now it has email/password auth (login + register) and a placeholder home screen. The only platform folder in the repo is **Android**. `lib/firebase_options.dart` throws `UnsupportedError` on other platforms, including web.

User-facing strings, error messages and some identifiers (e.g. `_turkceHata`) are in **Turkish**. Keep new UI text in Turkish. Commit messages are also written in Turkish, without diacritics.

## Commands

```bash
flutter pub get                          # install dependencies
flutter run                              # run on a connected Android device/emulator
flutter analyze                          # lint (flutter_lints; build/ and android/ excluded)
flutter test                             # run all tests
flutter test test/widget_test.dart       # run a single test file
flutter test --plain-name "<name>"       # run a single test by name
flutter build apk                        # Android release build
```

Note: `test/widget_test.dart` is the leftover counter template. It references `MyApp`, which doesn't exist (the root widget is `FitPulseApp`), so `flutter test` currently fails to compile until that test is rewritten. A real widget test also needs Firebase mocked, because `FitPulseApp` and `AuthRepository` reach `FirebaseAuth.instance` directly.

## Architecture

The code is organized by feature and uses MVVM with `provider`: `lib/features/<feature>/{repository,viewmodel,view}/`.

- **Repository** (`AuthRepository`): a thin wrapper around `FirebaseAuth.instance`. It exposes `authState` (`authStateChanges()` stream), `signIn`, `register` and `signOut`.
- **ViewModel** (`AuthViewModel extends ChangeNotifier`): holds `isLoading` and `errorMessage`. It catches `FirebaseAuthException` and turns error codes into Turkish messages. The repository is created inside the ViewModel, not injected.
- **View**: screens use `context.watch<AuthViewModel>()` and `context.read<AuthViewModel>()`.

Navigation is driven by auth state, not by routes. In `main.dart`, a single `ChangeNotifierProvider<AuthViewModel>` sits above `MaterialApp`, and `home:` is a `StreamBuilder` on `vm.authState` that shows `HomeScreen` when a user is signed in and `LoginScreen` otherwise. Signing in or out swaps the screen automatically, so don't `Navigator.push` after an auth call. `HomeScreen` currently reads `FirebaseAuth.instance.currentUser` directly instead of going through the ViewModel.
